\chapter{系统需求分析与总体设计}

本章在前述理论基础之上，进一步说明平台面向的核心需求、总体架构、数据模型与关键模块设计。与第4章侧重算法方法、第5章侧重工程实现不同，本章更关心系统为什么按当前方式划分模块、数据如何在模块之间流动，以及这些设计如何服务后续实现与验证。对本文而言，模块组织的中心仍然是综合风险分析主链，其余能力分别围绕输入补全、结果延伸和解释反馈展开。

\section{系统需求分析}

\subsection{功能需求分析}

结合目标用户与当前业务链路，平台首先需要解决的是多模态健康数据如何进入同一系统的问题。用户既可能直接录入结构化临床指标和基础画像，也可能上传体检报告，由 OCR 服务辅助提取可计算字段；遗传信息和行为相关状态则作为补充证据参与后续分析。换句话说，系统不能只面向某一种数据入口，而是要把档案录入、文档上传、历史记录与时间线展示组织成同一条输入链路，这也是后续风险分析能够稳定运行的前提。

在输入链路建立之后，系统还需要提供面向个体的分析能力。当前设计的重点是综合风险评估与情景化推演。前者要求平台能够在统一分析入口下组织临床、遗传和行为相关信息，并输出结构化风险结果；后者则进一步比较未来自然演化场景和干预调整场景下的风险变化，用于帮助用户理解不同方案可能带来的差异。对于主动健康管理场景而言，仅给出一次性风险结果是不够的，系统还需要把结果继续向比较和解释环节延伸。

除分析之外，平台还需要提供可解释的健康问答能力，使回答能够结合用户画像、历史分析结果和知识检索内容，并受到证据约束。家庭协同和后台管理虽已有实现基础，但在本章中仅作为扩展能力处理，设计主线仍聚焦数据进入平台后的分析、比较与解释。

\subsection{非功能需求分析}

在非功能层面，平台首先面对的是安全与隐私约束。健康档案、体检文档和遗传数据都具有较高敏感性，因此系统必须具备基本的用户鉴权、权限隔离与敏感字段保护能力。结合现有实现，用户访问依赖令牌校验，遗传信息通过加密字段保存，问答链路中的治理摘要与审计留痕则以结构化形式写入数据库，以支持后续追踪与回放。

除安全之外，平台还需要兼顾在线交互过程中的响应体验。风险评估、文档解析和问答服务都服务于用户直接可见的页面，因此设计上应尽量避免将较长时延的处理过程无差别堆叠到一次前端请求中。当前实现中，缓存属于可选增强能力而非唯一依赖，Redis 不可用时系统仍应维持主链可运行，这意味着平台设计更强调优雅降级，而不是把所有交互体验押注在某一个运行时组件上。

最后，平台还需要保持一定的扩展性与可维护性。考虑到健康指标字段、知识资料和问答治理逻辑都可能随着迭代继续扩展，系统设计采用前后端分离、服务分层以及“核心字段结构化、扩展信息半结构化”的组合方式，以尽量降低后续功能增加对整体架构的扰动。

\section{系统总体架构设计}

\subsection{平台总体架构}

结合仓库中的前端、后端与部署配置，平台总体上可概括为“前端交互层、后端服务层、数据与模型支撑层”三层结构。前端交互层基于 Vue 构建，负责健康档案录入、风险结果展示、时间线浏览以及 Dr.~AI 问答等界面组织，并通过统一路由区分普通用户与管理员入口。后端服务层基于 FastAPI 构建，承担用户认证、综合分析、文档解析、会话管理、问答治理和各类服务编排职责，是整个系统的主要业务承载层。数据与模型支撑层则由关系型数据存储、可选缓存以及风险评估、OCR、知识检索等运行时组件共同构成，用于支撑分析结果生成与状态持久化。

在这一结构中，Agent 健康问答模块位于后端服务层内部，与用户画像、风险分析结果、知识检索和审计记录协同工作。它复用平台已有健康上下文，将问答结果与风险分析结果放在同一交互入口下呈现，避免形成脱离主链的独立子系统。

\subsection{核心业务流程设计}

从核心业务流程看，平台的运行链路可以概括为“数据输入、统一分析、结果反馈、持续问答”四个环节。用户首先通过健康档案页面填写临床画像，或上传体检报告触发 OCR 解析；在有对应数据时，遗传信息和行为相关状态也会作为补充输入进入同一流程。随后，后端在统一分析入口下对多源数据进行整理与融合，生成结构化风险结果、分析上下文以及可供后续展示的解释信息。分析完成后，前端再通过仪表盘、风险卡片和时间线等视图组织展示，并在需要时调用未来风险模拟或干预模拟接口，向用户呈现不同场景下的变化趋势。

在结果反馈之后，Dr.~AI 问答模块进一步利用当前用户画像、历史会话和知识检索结果组织回答。当用户提出健康咨询、报告解读或趋势回顾类问题时，系统根据问题类型选择受限工具与证据来源，输出包含回答文本、证据标签和必要提示的结构化结果。也正因此，平台中的问答模块并不是与分析结果并行存在的另一套系统，而更像是对已有分析结果的解释入口和交互延伸。

\section{核心数据模型设计}

\subsection{关键实体与关系}

平台的数据模型主要围绕用户主体、健康观测、问答会话与治理留痕四类对象展开。用户账户由 \codeid{User} 实体负责认证与角色标识，\codeid{UserProfile} 与之构成一对一关系，用于保存临床画像、遗传信息和扩展健康字段。围绕用户主体，\codeid{HealthRecord} 用于保存历史观测快照，\codeid{MedicalDocument} 用于保存上传文档及其 OCR 处理结果，二者共同构成健康数据的历史积累基础。

在交互层面，\codeid{ChatConversation} 与 \codeid{ChatMessage} 用于组织对话会话及逐条消息内容，从而支持连续问答与历史回溯；\codeid{FamilyLink} 等家庭协同实体则作为扩展授权关系保留。围绕 Agent 问答治理，系统进一步引入 \codeid{AgentAuditEvent} 与 \codeid{AgentAnswerReplay}，用于保存车道判定、回答模式、证据充分性、工具使用摘要和回答回放快照，为审计、回归验证和问题排查提供结构化依据。

\subsection{多模态数据组织方式}

为兼顾结构稳定性与后续扩展需求，平台采用“核心字段结构化存储，扩展信息半结构化保存”的数据组织方式。对于年龄、血糖、糖化血红蛋白和血压等稳定临床指标，系统将其作为 \codeid{UserProfile} 的显式字段保存，便于后续分析服务直接读取。对于随时间变化的观测值及风险快照，系统通过 \codeid{HealthRecord} 进行按时间记录，从而支撑历史趋势展示与阶段性比较。

文档类输入则通过 \codeid{MedicalDocument} 承载文件路径、上传时间、OCR 处理状态和结构化摘要，使原始文件保存、解析状态追踪与结构化导入可以在同一对象下管理。对话类数据由会话实体和消息实体分别保存，以便同时支持最近消息窗口构建、历史检索和前端会话列表展示。对于问答治理中产生的证据面板、上下文预算摘要和工具调用摘要，系统使用 JSON 字段保存结构化扩展信息，以平衡模式稳定性与表达灵活性。

平台对遗传相关信息采用独立加密字段存储，而非混入普通文本字段，这既符合健康数据敏感性要求，也与当前代码中的属性访问和加解密逻辑一致。

\section{关键模块设计}

\subsection{风险评估模块设计}

风险评估模块是平台分析链路的核心入口，实际承担的是系统中的综合风险分析中枢。其主要任务是接收用户临床画像、遗传数据和部分行为相关信息，在统一分析接口下完成特征整理、风险估计与结果组织，并输出可供前端展示的风险报告和分析上下文。该模块在设计上强调统一入口与统一输出，目的在于避免不同数据源分别分析后难以汇总的问题。

从系统协同关系看，风险评估模块一方面与用户画像、历史记录和文档解析结果相连，负责消费结构化健康数据；另一方面又向仪表盘、时间线和问答模块提供统一的风险结果支撑。因此，它在整个平台中处于由输入走向决策的桥接位置，是第4章算法设计在工程层面的主要承载对象之一。

\subsection{干预推演模块设计}

干预推演模块建立在风险评估结果之上，主要提供未来风险模拟和干预情景比较两类能力。系统通过独立接口接收用户当前画像及目标干预参数，并输出自然演化场景或干预后场景下的风险变化结果。相较于直接给出静态建议，这一设计更强调结果之间的可比较性，有助于用户理解不同调整方案可能带来的风险变化方向。

在平台链路中，干预推演模块与风险评估模块共享核心输入字段，但其输出更侧重面向用户的解释与比较，因此会直接服务于趋势展示、时间线和干预建议交互。第4章将进一步说明其方法基础，第5章则对应其接口与服务实现。

\subsection{Agent健康问答模块设计}

Agent 健康问答模块承担平台中的智能交互功能。该模块接收用户自然语言问题，在会话上下文的基础上结合用户画像、历史分析结果、文档摘要和知识检索结果生成回答，并根据问题类型调用受限工具集完成补充查询。与普通问答不同，该模块的设计重点不在开放式生成，而在于受控调用、证据约束和结果留痕。

从模块边界看，Agent 问答模块将大语言模型视为可替换的外部生成服务，平台侧主要负责用户上下文组织、工具调用约束、证据检索和回答过程留痕。

从数据流角度看，问答模块以上一轮分析结果和当前会话状态为输入，输出回答文本、来源引用、证据标签、建议卡片以及必要时的人工接管提示，并将关键治理摘要写入审计与回放对象。具体运行链路将在第5章集中展开，本章只保留其模块定位与职责说明。

\section{本章小结}

本章围绕平台需求、总体架构、核心数据模型和关键模块展开设计说明。平台将结构化档案、OCR 文档输入、遗传与行为信息组织到统一分析链路中，形成以综合风险分析为中枢、以情景推演和受控 Agent 问答为延伸的总体结构。上述设计为后续算法建模、系统实现和实验验证提供了统一基础。
