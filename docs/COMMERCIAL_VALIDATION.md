# 🧪 商业化验证与增长实验计划 (Commercial Validation Plan)

## 1. 实验核心目标
在不接入真实支付系统（Stripe/支付宝）的前提下，通过模拟付费场景，收集用户的 **付费意愿 (Willingness to Pay, WTP)** 数据，验证核心功能是否具备变现能力。

---

## 2. 实验 A：专业报告的“假门测试” (The Fake Door)

### 2.1 实验假设
用户为了获得一份可打印、去水印、不仅有数据的专业 PDF 报告，愿意付费订阅 Pro 会员。

### 2.2 交互设计 (UI/UX)
1.  **入口**：在“全周期健康管理”或“Dr. AI”页面，放置显著的 **“导出专业医疗报告 (PDF)”** 按钮，并在旁边加上 `👑 Pro` 图标。
2.  **触发**：用户点击按钮。
3.  **阻断 (The Paywall)**：弹出精美的“会员权益模态框”：
    *   标题：“升级到 Pro，获取专业医疗级报告”
    *   权益列表：✅ 去除水印 ✅ 高清矢量图 ✅ 包含未来5年风险推演 ✅ 医生认可格式
    *   价格锚点：原价 ¥299/年，限时特惠 ¥199/年。
    *   **行动按钮 (CTA)**：“立即升级” (主按钮) / “以后再说” (次按钮)。
4.  **反馈 (The Reward)**：
    *   当用户点击“立即升级”后，**不跳转支付**，而是显示 Toast/弹窗：
    *   *文案*：“🎉 感谢您的支持！Pro 功能目前处于内测阶段，**本次免费为您开通使用权限**！正在为您生成报告...”
    *   随后正常执行 PDF 生成逻辑。

### 2.3 数据埋点 (Metrics)
*   `pdf_export_click`: 导出按钮点击数 (意向基数)。
*   **`pro_upgrade_click`: 升级按钮点击数 (核心指标，代表强付费意愿)。**
*   `fake_door_conversion_rate`: `pro_upgrade_click` / `pdf_export_click`。

## 3. 实验 B：“亲情守护”的情感化增长

### 3.1 实验假设
子女对于父母的健康状况有强烈的焦虑感。如果有具体的异常数据预警，子女愿意为了“监控父母健康”而付费或高频使用。

### 3.2 场景设计
1.  **触发器**：当子账户（父母）上传的体检单中出现 **高风险指标**（如 SBP > 160 或 血糖 > 11）。
2.  **行动**：系统向主账户（子女）发送一条高优先级的 Notification 或短信模拟。
    *   *文案*：“【健康预警】Dr. AI 检测到您父亲（王建国）今日提交的血压数据偏高 (165/95)，建议复查。点击查看详细解读及饮食建议 >>”
3.  **转化点**：点击通知进入详情页后，展示“开通家庭守护 Pro，解锁 24小时异常监控与医生专线”。

### 3.3 数据埋点
*   `family_alert_open`: 预警通知的打开率。
*   `family_pro_interest`: 详情页中 Pro 介绍的停留时长或点击数。
