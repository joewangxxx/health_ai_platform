# 注释规范（P0）
本规范用于 Health AI Platform 的“高价值注释补充”，目标是提升可维护性，而不是堆砌注释数量。

## 1. 注释原则

- 注释 `why`（为什么这样做），而不是重复 `what`（代码本身在做什么）。
- 注释边界条件：失败路径、降级策略、兼容旧数据策略。
- 注释契约关系：与 `docs/api-contract.md`、`docs/data-model-contract.md` 的对应点。
- 注释副作用：写库、状态重置、缓存命中/失效、排序规则。

## 2. 必须补注释的场景

- 模块入口：文件头说明模块职责与边界。
- 复杂函数：分支多、跨服务依赖多、存在兜底逻辑。
- 关键数据转换：legacy -> canonical 的字段映射与截断策略。
- 前端状态流：SSE 流程、回退流程、批量操作预检与执行分离。

## 3. 禁止的低价值注释

- 逐行翻译代码（例如“给变量赋值”）。
- 与代码不一致的过期注释。
- 复制接口字段名但不解释语义边界。

## 4. 建议模板

### 4.1 模块头注释

```python
"""
模块职责、边界、以及关键降级策略。
"""
```

### 4.2 函数注释

```python
def fn(...):
    """
    目的：
    输入/输出：
    关键副作用：
    失败与降级：
    """
```

### 4.3 前端复杂流程注释

```js
// 中文注释：见下方实现逻辑。
```

## 5. 验收清单（PR 自检）

- 复杂文件是否有模块级注释？
- 关键函数是否写明副作用与失败路径？
- 是否避免“废话注释”？
- 注释是否与当前实现一致？
- 是否未引入任何业务逻辑变化（本次注释任务要求）？
